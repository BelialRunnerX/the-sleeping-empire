Power and logistics

Native development snapshot · Reviewed 18 November 2026

Conveyors, storage, loaders and batteries connect existing machine owners. They do not create a separate inventory authority.

Version matters. This is an implementation reference, not a promise that every feature is in your installed build. Provisional adaptations and limitations are stated explicitly. Controls describe the documented native snapshot and may differ in the Windows GUI handoff.

Network storage

A powered fabricator makes a Network Storage kit from 1 Machine Casing, 2 Control Circuits and 2 Copper Wire in 6 seconds. These costs are provisional. Automated same-network access requires enabled, powered storage; manual deposit and withdrawal can remain available offline.

Local-first resources

Workshops consume local inputs before network storage. Output stays local when it fits and spills only when local capacity is insufficient. This proximity-network abstraction is distinct from physical conveyor motion.

Batteries

Battery kits are placed empty. Existing generation charges them; capacity is 60 and charge/discharge rate 15 in the documented solver. Residual energy is not erased merely because it cannot meet a full tick’s demand. Recovery refuses positive charge.

Conserving recovery

The documented Shift+H Build action transfers an entire disabled battery’s charge into a disabled empty nearby battery. It copies the exact stored value, then empties the source, rather than adding/rounding partial charges. This is a live action; only a subsequent ordinary save persists it.

Extraction and routing

Extractor output can feed a belt, but the endpoint is output-only: belts cannot deposit into it. Mining requires power; enabled buffered output can drain without power. Cargo Loader kits connect existing belt and storage behavior. These local-host operations are not remote access control or WAN replay protection.
